# Untether — BLE protocol v1

Phone = GATT peripheral (server), Mac = central (client).

v1 was frozen with ops `0x01`–`0x03` and the base state keys. Everything added
later is backward compatible: new ops, new ATT errors and optional state keys
that readers ignore when they do not know them. Such additions are marked *(v1.1)*.

## UUIDs

| Name | UUID | Properties | Security |
|------|------|------------|----------|
| service | `13f60001-33cc-47ff-8e19-0a93d1157c5b` | primary, advertised | — |
| `nonce` | `13f60002-33cc-47ff-8e19-0a93d1157c5b` | read | encrypted |
| `command` | `13f60003-33cc-47ff-8e19-0a93d1157c5b` | write with response | encrypted |
| `state` | `13f60004-33cc-47ff-8e19-0a93d1157c5b` | read, notify | encrypted |
| `pairing` | `13f60005-33cc-47ff-8e19-0a93d1157c5b` | read | encrypted |

"Encrypted" = the link must be encrypted with a bonded key. The first access
from an unbonded Mac triggers LE pairing (LE Secure Connections when both
sides support it; numeric comparison is shown on both screens).

Advertising: flags + the 128-bit service UUID, no name. Mode *balanced*
(~250 ms), connectable. Advertises all the time while the service runs.

## Pairing (one time)

1. On the phone the user taps **Pair Mac**. A 60 s pairing window opens.
2. On the Mac the user clicks **Pair…**. The Mac scans for the service UUID,
   connects and reads `pairing`. macOS and Android show the bonding dialog;
   the user confirms the same code on both.
3. While the window is open `pairing` returns the pairing record (CBOR map):

   | key | type | meaning |
   |-----|------|---------|
   | `k` | bstr(32) | shared secret for HMAC |
   | `s` | tstr | hotspot SSID |
   | `p` | tstr | hotspot passphrase, empty for an open network |

   Outside the window it fails with ATT error `0x83`. The window closes
   60 s after it was opened.
4. The Mac stores `k`, `s`, `p` in the Keychain. The phone keeps them
   encrypted with an Android Keystore key.

The secret, SSID and passphrase are generated by the phone on first start.
With **Use Android's hotspot settings** on, `s` and `p` are the network set in
Android's own hotspot settings instead. A different network on the phone (a
switch of that option, or new Android settings) requires pairing the Mac again;
the Mac notices the different `ssid` in `state` and says so.

## Commands

1. Read `nonce` → 16 random bytes.
2. Write `command` (49 bytes, plus an argument for some ops):

   ```
   op(1) ‖ nonce(16) ‖ arg(0–64) ‖ HMAC-SHA256(k, op ‖ nonce ‖ arg)(32)
   ```

   | op | arg | meaning |
   |----|-----|---------|
   | `0x01` | — | ON — start Wi-Fi tethering with the paired SSID/passphrase |
   | `0x02` | — | OFF — stop Wi-Fi tethering (whoever started it) |
   | `0x03` | — | STATUS — notify `state` now |
   | `0x04` | — | RING — toggle find-my-phone (alarm + vibration, stops after 20 s) *(v1.1)* |
   | `0x05` | MAC, 6 bytes | BLOCK — add a client to the hotspot blocklist; it is dropped at once *(v1.1)* |
   | `0x06` | — | UNBLOCK_ALL — clear the blocklist *(v1.1)* |
   | `0x07` | subscription id, int32 BE | SET_DATA_SIM — use this SIM for mobile data *(v1.1)* |
   | `0x08` | — | RECONNECT_DATA — mobile data off and on again *(v1.1)* |
   | `0x09` | — | STOP_FIND_MAC — clear the phone's find-my-Mac request *(v1.1)* |

   The value may arrive as a single write or as a long (prepared) write.
3. The server regenerates `nonce` after **every** write to `command`,
   accepted or not. A nonce is therefore single-use; replayed or
   out-of-order frames fail.
4. Write response:

   | ATT status | meaning |
   |------------|---------|
   | `0x00` | accepted; the result shows up in `state` |
   | `0x80` | rejected: wrong length, stale nonce or bad HMAC (not distinguished) |
   | `0x81` | unknown op (HMAC was valid) |
   | `0x82` | impossible now: Shizuku not running or no permission (ops `0x01`, `0x02`, `0x05`–`0x08`) |
   | `0x84` | ON refused: battery below the battery-guard threshold and not charging *(v1.1)* |

   HMAC comparison is constant-time.

## State

`state` holds one CBOR map (≤ 512 bytes). A notification carries the same
bytes; when the value is longer than ATT_MTU − 3 the notification carries
an empty value and the Mac reads the characteristic (long read).
The server notifies on every change and at least every 60 s *(v1.1)*; the Mac
treats 150 s without state on a live link as a dead link and reconnects.

| key | type | meaning |
|-----|------|---------|
| `v` | uint | protocol version, `1` |
| `hs` | uint | hotspot: 0 off, 1 starting, 2 on, 3 stopping, 4 error |
| `err` | int | error code, present only when `hs = 4` (tethering error code; `-1` = AP failed) |
| `ssid` | tstr | SSID of the running hotspot, present when `hs = 2` |
| `cl` | array | clients: map `{mac: tstr, ip?: tstr, n?: tstr}` (hostname `n`) |
| `ncl` | uint | total number of clients (`cl` may be cut to fit 512 bytes) |
| `bat` | uint | battery % 0–100 |
| `chg` | bool | charging |
| `net` | uint | cellular: 0 none, 1 3G (or older), 2 LTE, 3 5G NSA, 4 5G SA |
| `sig` | uint | signal level 0–4 |
| `shz` | uint | Shizuku: 0 ok, 1 not running, 2 no permission |
| `op` | tstr | mobile operator name *(v1.1, optional)* |
| `rsrp` | int | RSRP, dBm (5G if present, else LTE) *(v1.1, optional)* |
| `snr` | int | SINR, dB *(v1.1, optional)* |
| `temp` | int | battery temperature, °C *(v1.1, optional)* |
| `sims` | array | active SIMs: map `{id: int, n: tstr}` *(v1.1, optional)* |
| `dsim` | int | subscription id used for mobile data *(v1.1, optional)* |
| `blk` | uint | clients on the blocklist, present when > 0 *(v1.1)* |
| `bmin` | uint | battery-guard threshold %, present when enabled *(v1.1)* |
| `ring` | bool | find-my-phone is ringing, present when true *(v1.1)* |
| `fmac` | bool | the phone asks the Mac to play a sound, present when true *(v1.1)* |
| `wifi` | uint | 0–4, present while the phone's own internet is Wi-Fi, which the hotspot then shares *(v1.1, optional)* |
| `bye` | bool | sent alone with `v` as the last notification when the user stops Untether on the phone; the Mac drops the link *(v1.1)* |

Readers must ignore unknown keys.

## Hotspot state machine (phone)

```
          AP ENABLING             AP ENABLED
   off ───────────────► starting ───────────► on
    ▲                      │                  │
    │ next command         │ AP FAILED /      │ AP DISABLING
    │ or AP ENABLING       │ start failed     ▼
    └──────────────────── error        stopping ──► off (AP DISABLED)
```

Transitions come from the system (`WIFI_AP_STATE_CHANGED`, tethering
callbacks), never from the fact that a command was sent. ON/OFF commands and
changes made on the phone itself (quick settings) take the same path.
`error` survives the `AP DISABLED` that follows a failure and is cleared by
the next command or `AP ENABLING`.

## Mac flows

- **ON:** connect (if needed) → read `nonce` → write ON → wait for
  `hs = 2` (timeout 15 s) → join Wi-Fi `s`/`p` unless already on `s`.
- **OFF:** read `nonce` → write OFF → leave Wi-Fi `s` if joined.
- The Mac connects to the first peripheral that advertises the service,
  stays connected and subscribed to `state` while the phone is in range, and
  reconnects automatically.
- **Find my Mac** *(v1.1)*: while `fmac` is true the Mac shows the popover and
  plays a sound; its Stop button sends `0x09`. The phone clears `fmac` by
  itself after 30 s.
